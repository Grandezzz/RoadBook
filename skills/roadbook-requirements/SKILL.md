# RoadBook 需求记录

以项目根目录下 `REQUIREMENTS.md` 为统一需求记录，`README.md` 保留项目介绍、运行方式与已实现功能。路径相对于包含本技能的项目根目录。

- 开始处理需求前先读现有记录，沿用编号与上下文。用户在对话中提出的新功能、交互/视觉调整、约束、缺陷反馈及需求变更，都要在同一轮工作中记入需求文档，尽量在实施前记录。
- 每条记录包含稳定编号、提出日期、来源、用户意图、可核验的验收条件、状态及验证情况。不要把助手建议、代码推测或已有功能当作用户曾经提出的需求。
- 有歧义时先记录已知内容和待确认点；不要为了填满模板擅自补充功能。普通咨询或代码解释无需虚构新需求。
- 需求调整保留原编号并记录变更日期及变更内容；明确替代或取消时保留历史，标注被哪条需求替代或已取消。
- 完成工作后更新状态，可用“待确认、待实现、进行中、已完成、已取消”。只有验收条件已满足才标记已完成；代码检查、自动测试、浏览器检查和真机验证须如实区分，未验证的部分明确写出。
- 找不到历史需求时说明缺失，不依据 README 或代码伪造历史。将现有功能摘要和助手发现的问题单独标注来源，待用户要求实施时再转为需求。
- 最终回复简要说明本轮记录或更新的位置；本技能不授权额外功能开发、发布或外部操作。
